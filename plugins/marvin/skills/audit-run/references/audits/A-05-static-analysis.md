# A-05 — Статический анализ кода

> **Audit question.** What is the measurable state of the codebase, and how much of its discipline is enforced automatically rather than on trust?

## 1. Role and task

An engineer measuring a codebase they did not write, then checking whether the project's own tooling would have
caught what the measurement found. It closes one question: which share of the code sits outside defensible limits,
and is enforcement tightening or eroding. It leaves the §8 metric tables and the suppression chronology behind it.

## 2. Audit-specific parameters

**The measured population is the contract's.** `report-contract.md` §2 defines the exclusion set once, in three
machine shapes: `GIT_EXCLUDE` for every git command here, `RG_EXCLUDE` for every ripgrep census, `EXCLUDE_RE` to
filter a path list already in hand. The three are **not** interchangeable, and what follows re-expands the
contract's array rather than re-encoding its list. The one addition is `GENERATED_GLOBS`, bound here because §2's
derivations use it:

```sh
EXCL=( "${GIT_EXCLUDE[@]}" )                                  # report-contract.md §2, unmodified
for p in "${GIT_EXCLUDE[@]}"; do EXCL+=( "${p/\*\*\//}" ); done   # each glob again at depth 0 — measured: a pathspec `**/` needs one leading directory, so `:(exclude)**/dist/**` prunes sub/dist/ and leaves top-level dist/ IN
for p in "${GENERATED_GLOBS[@]}"; do EXCL+=(":(glob,exclude)$p"); done
```

| Parameter | Meaning | Default and derivation when unset |
|---|---|---|

This audit's unit is already the file, so it consumes the ranking as it stands and aggregates nothing | derive with the contract's `GIT_EXCLUDE` already in the shell: `git log --no-merges --since='18 months ago' --name-only --pretty=format: -- . "${GIT_EXCLUDE[@]}" \| sed '/^$/d' \| sort \| uniq -c \| sort -rn \| head -30`, joined to file length from `git ls-files -- . "${GIT_EXCLUDE[@]}" \| xargs wc -l`. ## 3. Scope

### In scope

Cyclomatic and cognitive complexity, function and file length, nesting depth, parameter counts, duplication, dead
code (unused exports, unreferenced files, unreachable branches), the linter configuration itself, and the history of
its weakening.

### Out of scope

- **Types, `any`, unchecked casts** → A-06, and with them every **type-checker** suppression (`@ts-ignore`,
  `@ts-expect-error`, `@ts-nocheck`, `# type: ignore`, `@psalm-suppress`): A-06 counts that population, this audit
  counts **linter** suppressions only, and neither files the other's.
- **Component size, prop drilling, bundle shape** → A-13, and with them the **length of any file under
  `CLIENT_ROOT`**: A-13's T10 bands file those, and §4 step 1 subtracts that tree from the length population so one
  component is not filed twice at two severities. Complexity and duplication are still measured there.
- **Dependency currency and licences** → A-03; plugin versions are read here only to record which rule sets exist.
  **Performance** → A-15: complexity is not latency, and N+1 query patterns are A-15's row, not this audit's.
- **Test quality, coverage, flakiness** → A-07; the test cohort is measured here for size and duplication only,
  reported separately in the appendix and never folded into `OUT`.
- **Module boundaries, layering, cycles** → A-09; duplication *across* modules is a metric here and a boundary
  violation there. **Security-relevant patterns** → A-14; a disabled security rule class is an enforcement gap here, cross-referenced.

## 4. Collection protocol

**Step 0 — fix the measured population before measuring anything.** Take the `EXCL` array of §2, then filter what it
leaves through `EXCLUDE_RE`, which carries six classes the git shape does not — `pnpm-lock.yaml`, `__pycache__/`,
`*.map`, `*.generated.*`, `*_pb2.py`, `*.pb.go`:

```sh
git ls-files -z -- . "${EXCL[@]}" | tr '\0' '\n' > "$OUTPUT_DIR/scope.raw"
grep -vE "$EXCLUDE_RE" "$OUTPUT_DIR/scope.raw" > "$OUTPUT_DIR/scope.txt"
echo "tracked=$(git ls-files | wc -l) pathspec=$(wc -l < "$OUTPUT_DIR/scope.raw") in_scope=$(wc -l < "$OUTPUT_DIR/scope.txt")"
```

`scope.txt` is what every later step reads, and by construction no `EXCLUDE_RE` class survives into it. The residue
`pathspec − in_scope` is the pathspec's own shortfall: above 5% of `pathspec` the git shape is doing little and the
population rests on the regex alone, which *Методология* then says. Produces the in-scope list and both line
totals, in-scope and excluded. Seconds.

1. **Whole-base metrics** over the whole in-scope population, not a sample: cyclomatic and cognitive complexity,
   function length, file length, nesting depth, parameter count — **file length alone over `scope-len.txt`**, the
   in-scope list minus A-13's `CLIENT_ROOT` (§3), which §5's first row builds, so that tree is subtracted before
   measurement rather than filed here and withdrawn afterwards. Run the stack's tool (§5) with the §6 numbers as
   rule arguments so it emits one record per breach. Produces one row per unit (`path:line, metric, value`) plus
   each metric's distribution — n, p50, p90, p99, max — from
   `sort -n | awk '{a[NR]=$1} END{m=int((NR-1)*0.5)+1;p=int((NR-1)*0.9)+1;q=int((NR-1)*0.99)+1;printf "n=%d p50=%d p90=%d p99=%d max=%d\n",NR,a[m],a[p],a[q],a[NR]}'`. Minutes; one pass over the tree.
2. **Duplication.** Pin and record `--min-lines` and `--min-tokens`: the percentage means nothing without them. Produces
   the duplicated share, the ten largest clones with both locations and line counts, and the cross-module subset. Minutes.
3. **Dead code**: unused exports, files nothing imports, unreachable branches. Each kind has its own §5 row and §6
   threshold, except **handlers for removed states, which are not machine-detectable**: they come only from step 6's
   reading, reported as such and never as a zero. Produces counts by kind, the appendix list and the unused export
   share; the hand-check of ten or more candidates is the slow part — dynamic imports, DI and reflection over-report.
4. **Linter configuration audit.** Per `LINT_CONFIG_PATHS` entry: how many rules are off against the
   tool's own recommended set, and which commit turned each off when (`git log --format='%h %ad %s'
   --date=short -- <config>`, then `git log -p -- <config>` for the hunks); then inline suppressions now
   versus at the `TREND_WINDOW` baseline. **The counted set is fixed here** — an executor who picks
   their own patterns makes two runs incomparable, and this count is what §9's `S` means. It holds
   linter directives only; a type-checker directive on the same line is A-06's population (§3):

   | Stack | Extended regex counted |
   |---|---|
   | JS / TS | `eslint-disable(-next-line\|-line)?\|biome-ignore` |
   | Python | `#[[:space:]]*(noqa\|pylint:[[:space:]]*disable)` |
   | Go / Ruby / Rust / PHP | `//[[:space:]]*nolint`; `rubocop:disable`; `#\[allow\(`; `phpcs:ignore` |

   Count at both revisions with `git grep -cE '<regex>' <sha> -- . "${EXCL[@]}" | awk -F: '{s+=$NF} END{print s+0}'`,
   running only the rows the stack contains. Produces the disabled-rule list with dates and commits, the two counts
   with per-stack subtotals, and the delta; the report records which rows ran. Read the object database, never a
   checkout. Minutes.
5. **Zero-tolerance run**, twice, both reported: the project's own config at `--max-warnings 0` or its equivalent, and
   the tool's stock recommended config with inline suppressions ignored — the difference is the deferred debt.
   "Stock" is not left to judgement: it is the config body pinned in §5, or the tool's built-in default where it has
   one. Produces a total problem count per run and the counts aggregated **by rule id**, never by occurrence. Minutes.
6. **Manual reading of the top five `HOTSPOTS`**, in full: what the unit is responsible for, which responsibilities do
   not belong to it, which invariant is implicit, what shape the fix takes. Produces five prose blocks for §8, each
   naming the `F-A05-NN` ids it generated, or stating that the file crosses nothing and reads cleanly — also a result.

## 5. Tools

Every row degrades to its fallback and the run continues. Tooling is acquired by `report-contract.md` §9 and this
spec states no policy of its own. When a fallback chain ends with no number at all, the **metric** goes into
`tools_unavailable` (`cognitive complexity (no SonarQube, no sonarjs)`, `parameters per function (Go)`) and the §6
row it feeds is skipped, never graded against a proxy on another scale.

| Tool | Measures | Invocation | Fallback when absent |
|---|---|---|---|
| `git` + POSIX, `scc` / `cloc` / `tokei` | scope, sizes, distributions, history, the KLOC denominators | build the length population once — `cp "$OUTPUT_DIR/scope.txt" "$OUTPUT_DIR/scope-len.txt"; for d in "${CLIENT_ROOT[@]}"; do grep -v -e "^${d%/}/" -e "^${d%/}$" "$OUTPUT_DIR/scope-len.txt" > "$OUTPUT_DIR/.len"; mv "$OUTPUT_DIR/.len" "$OUTPUT_DIR/scope-len.txt"; done` (an empty `CLIENT_ROOT` leaves the two files identical) — then `tr '\n' '\0' < "$OUTPUT_DIR/scope-len.txt" \| xargs -0 wc -l \| grep -v ' total$' \| sort -rn` for §6's length rows, and the same over `scope.txt` for the KLOC denominators; `scc --by-file --format json .` for LOC by language | none needed — `wc -l` over the scope list is the floor |
| ESLint (JS/TS) | complexity, lengths, depth, params | `npx --no-install eslint . --rule '{"complexity":["error",10],"max-lines-per-function":["error",50],"max-depth":["error",4],"max-params":["error",5]}' --format json` — `--rule` merges over the project config, so parsers and plugins still resolve. `max-lines` is deliberately not in that set: it runs alone, past A-13's tree — `IGN=(); for d in "${CLIENT_ROOT[@]}"; do IGN+=(--ignore-pattern "${d%/}/**"); done; npx --no-install eslint . --rule '{"max-lines":["error",400]}' "${IGN[@]}" --format json` | file lengths from `wc -l` over `scope-len.txt` plus the manual read; record that per-function metrics were not measured |

## 6. Analysis rules and thresholds

`QUALITY_GATE`, when supplied, replaces any row it covers; the report names which rows and with what.

| Condition | Threshold | Severity | Origin |
|---|---|---|---|
| Cyclomatic complexity per function | > 10 / > 20 | `S3` — candidate / `S2` | requirements |
| Cognitive complexity per function, from SonarQube or `eslint-plugin-sonarjs` only | > 15 / > 30 | `S3` / `S2`; unmeasured on any other stack, and then the row is skipped rather than approximated | derived |
| Function length | > 50 lines | `S3` — candidate | requirements |
| File length, over `scope-len.txt` (§4 step 1: in-scope minus `CLIENT_ROOT`) — A-13's T10 files a component's length | > 400 / > 1000 lines | `S3` — candidate / `S2` | requirements |
| Nesting depth | > 4 | `S3` | derived |
| Parameters per function | > 5 | `S4`; `S3` when the function also crosses a length or complexity row | derived |
| Duplicated share of in-scope lines | 3–5% / > 5% | `S3` / `S2` | requirements |
| One clone spanning two top-level modules | ≥ 30 duplicated lines | `S2`, cross-referenced to A-09 | derived |
| Unused exports | > 5% of exported symbols, or > 20 unreferenced files | `S3` | derived |
| Unreachable branch: unreachable statement, constant condition, `case` fallthrough | any / > 10 | `S3` / `S2` | derived |
| Growth of linter suppressions over `TREND_WINDOW` | any increase | `S2`, one dedicated finding; flat or declining is `S4` and still reported | requirements |
| Blanket disable: file-wide `/* eslint-disable */`, bare `# noqa`, `//nolint` naming no linter | any occurrence | `S2` | requirements |
| Linter suppression carrying no justification comment | each instance; ≥ 30% of this audit's suppression population | `S3` each; `S2` in aggregate — the same pair A-06 §6 applies to its own type-checker population | derived |
| Rule off in config: correctness class (unused vars, undefined names, `eqeqeq`, floating promises) / stylistic | any | `S2` / `S4` | requirements |
| Stock-config zero-tolerance backlog | > 20 problems per KLOC; > 50 | `S3` / `S2` | derived |

The contract's position override needs one audit-specific input: absent `BUSINESS_CONTEXT`, the critical path is
recognised by path name (`auth`, `payment`, `billing`, `token`, `crypto`). This audit's ceiling is `S2`: a
code-health metric alone is never an `S1`. A row with no measurement path is skipped, never estimated (§5).

## 7. Budget and stopping

Deltas from `report-contract.md` §8 only.

The sampling unit is **one in-scope source file**. Top `N` ranking, in order: (1) how many §6 thresholds the file
crosses, (2) its `HOTSPOTS` rank, (3) file length. The first five `HOTSPOTS` entries are read whether or not they
cross anything and count inside `N` — step 6 is not optional at any `DEPTH`. The control sample `C` is drawn from
files crossing **no** threshold, so it tests the thresholds and not only the ranking. Early stop: the contract's
control-sample stop, additionally requiring that step 5's by-rule aggregate no longer adds rule ids.

## 9. Score

Two numbers, always reported together. **Out-of-threshold share:** `OUT = 100 × (lines in units crossing at least one
§6 threshold) / (in-scope lines)`. Unit: percent of in-scope lines. A unit is a function where the tool reports per
function and the file otherwise; a line crossing several rows counts once.

**Suppression trend.** `TREND = 100 × (S_now − S_base) / S_base`, where `S` is the §4 step 4 count at `HEAD` and at
the `TREND_WINDOW` baseline. Unit: percent over the real window length, stated beside it. **Not computed when
`S_base` < 10, or when the real window is shorter than `TREND_WINDOW`** — off a tiny baseline the percentage is
always alarming and never informative. Report `S_now − S_base` and `S_now` per KLOC instead, mark `TREND` not
computed with the reason, and repeat it in *Границы достоверности*.

Rows are evaluated top to bottom and **the first match is the band**. With `TREND` not computed, band on `OUT`
alone — ≤ 10% Controlled, ≤ 25% Drifting, above that Large but stable — and name the missing half beside it.

| Band | Condition |
|---|---|
| Out of control | `OUT` > 25% and `TREND` > 0 |
| Eroding | `TREND` > +25% |
| Large but stable | `OUT` > 25% and `TREND` ≤ 0 |
| Controlled | `OUT` ≤ 10% and `TREND` ≤ 0 |
| Drifting | everything else |

The justification names which metric dominates `OUT`, whether its mass is concentrated in a few units or spread
evenly, and whether the trend comes from new rules adopted or old rules disabled.

## 10. Failure modes of this audit

Each row is a way **this** audit returns a number that is wrong while looking right.

| Failure mode | How the false result appears | Countermeasure |
|---|---|---|
| Measuring code nobody wrote | generated clients, protobuf output, vendored libraries, migration bodies and minified bundles dominate every distribution and duplication figure, and the run exits 0 while doing it | the contract's §2 arrays are the only ones used, and step 0 ends by filtering its own output through `EXCLUDE_RE`, so no gap between the three machine shapes can leak a generated path into the population. Step 0 also prints its three totals: an excluded share above 40% or below 1% means the detection is wrong, so re-derive `GENERATED_GLOBS` before continuing |
| Measuring code written to other rules | long, repetitive test files are normal and their duplication is often deliberate, so they inflate lengths and clone share | report the `TEST_GLOBS` cohort separately with its own numbers; never fold it into `OUT`, never drop it silently |
| A thousand warnings filed as findings | the register becomes a data dump and the ten rules that actually matter are invisible | never one finding per occurrence: aggregate by rule id, file the ten most frequent rules as a handful of findings, put the by-rule table in the appendix, and state what was cut |
| A tool that ran but linted nothing | a config resolution failure or a flat-config major change yields an empty result that reads like a clean codebase | compare the file count the tool reports against `wc -l < "$OUTPUT_DIR/scope.txt"`, or `scope-len.txt` for the `max-lines` run; refuse to report any metric from a run covering under 80% of it |
| A duplication percentage with no parameters | the same repository reads at 2% or 15% depending on `--min-lines` | the number never appears without both parameters beside it; the fallback proxy is reported as a count, never a percentage |
| History measured wrong | `git log -S` counts commits that changed the number of occurrences, not the occurrences; on a repository younger than `TREND_WINDOW` the `--before` lookup returns empty; one Prettier or `gofmt` sweep inflates churn and moves every suppression | take levels from `git grep -c` at two revisions and use `git log -S` only to attribute a change; fall back to the root commit and state the real window; find sweeps with `git log --format='%h %s' --shortstat` and exclude any commit touching over 20% of in-scope files from the chronology |
| A trend computed off a baseline of two | arithmetically correct and editorially false: a young repository with three justified suppressions reports `TREND` = +300%, bands as *Eroding* — the worst-but-one verdict — and the summary says the project is losing control of its linter | apply the §9 floor: below `S_base` = 10, or on a short window, report the absolute delta and the per-KLOC rate, mark `TREND` not computed, and band on `OUT` alone |
| A dead-code tool believed | dynamic imports, DI containers, reflection, framework entry points and public library surfaces all read as unused | hand-verify ten or more candidates before filing; the unverified remainder is `confidence: hypothesis` with its check named |
| Taste filed as a defect | long is not complex, and a 300-line exhaustive `switch` is not a finding | every finding cites the §6 row it crosses; a unit crossing none is preference under `report-contract.md` §5 |

## 11. Audit-specific prohibitions

| Forbidden | What it would mutate | Safe alternative |
|---|---|---|
| `eslint --fix`, `ruff check --fix`, `ruff format`, `prettier --write`, `gofmt -w`, `black`, `rubocop -a` | rewrites source files wholesale | `eslint --fix-dry-run --format json` when the count of auto-fixable problems is wanted; otherwise report only |
| Any file written outside `OUTPUT_DIR`, in or out: tool output left at its default location, or a generated input placed where a tool can find it | jscpd writes `./report`, Sonar `.scannerwork/`, `ruff` `.ruff_cache/`, ESLint `.eslintcache`; and a stock config dropped at the repository root to make an import resolve mutates the audited tree, taking the next run's baseline with it | point every output at `OUTPUT_DIR` — jscpd `--output`, `-Dsonar.working.directory` — pass `--no-cache` to `ruff`, never `--cache` to ESLint, and write the stock config into `OUTPUT_DIR` with an absolute module path (§5). A tool that insists on writing elsewhere is not run, and its metric is recorded unmeasured |
